Commands from the session

These run in the Terminal app on macOS. Most also work on Linux; where they differ, the Linux version is in the comment.

The rule. Only scan, probe or test machines you own or have written permission to test. Everything below runs on your own computer or your own lab virtual machine.

The machine alone: accounts and permissions

$ whoami                                  # the account, not the person
$ mkdir -p ~/demo && echo "my secret plans" > ~/demo/secret.txt
$ ls -l ~/demo/secret.txt                 # -rw-r--r--  owner can write, everyone can read
$ ps -eo pid,user,comm | head -15         # programs running right now
$ chmod 000 ~/demo/secret.txt             # nobody may read it
$ cat ~/demo/secret.txt                   # Permission denied
$ sudo cat ~/demo/secret.txt              # privilege escalation: the admin reads it anyway
$ chmod 644 ~/demo/secret.txt             # reset

Reading -rw-r--r--: the first character is the type, then three letters each for the owner, the group and everyone. r read, w write, x execute, - no.

Your machine on the local network

$ ipconfig getifaddr en0                  # your private IP (try en1)   Linux: ip -4 addr
$ route -n get default | grep gateway     # your router                 Linux: ip route
$ ping -c 4 $(route -n get default | awk '/gateway/ {print $2}')
$ arp -a                                  # devices your machine has talked to

Scan and close the doors on your own lab machine

Needs Multipass and nmap on your computer, and a lab VM you created yourself.

$ multipass launch --name lab             # your own Ubuntu VM
$ multipass exec lab -- sudo apt-get install -y nginx   # give it a web server to find
$ multipass info lab | grep IPv4          # note the lab IP
$ nmap -sV <LAB_IP>                       # 22/tcp ssh, 80/tcp http: two open doors

# default deny, then allow only what you need
$ multipass exec lab -- sudo ufw allow 22/tcp
$ multipass exec lab -- sudo ufw default deny incoming
$ multipass exec lab -- sudo ufw --force enable
$ nmap -sV <LAB_IP>                       # port 80 is now filtered

$ multipass exec lab -- sudo ufw --force disable        # reset

Spot the phish

Every scam in the session had one tell. Learn the tells, not the messages.

Bad grammar used to be the tell. AI removed it. The rule that still works: verify through a second channel you already trust.

How passwords should be stored

The eight steps of the password ladder, from worst to best. If you build a login, aim for the bottom of the list.

  1. Plaintext. One leak and every account is gone.
  2. Hashed. Unreadable, but not safe yet.
  3. Rainbow tables. Attackers do not crack common passwords, they look them up.
  4. The second leak. The same stored value means the same password.
  5. Salt. A random value per user, so the same password stores differently and lookups fail.
  6. Still guessable. Fast hashes allow billions of guesses a second. Salt made them work, not slow.
  7. Slow hashing. Use bcrypt, scrypt or Argon2, which are designed to be slow.
  8. Pepper, and after a leak. Keep a secret outside the database. After a leak: reset passwords, end every session, re-hash, notify within 72 hours, and check for reused passwords.

Check your own email at haveibeenpwned.com, and see what your browser gives away at coveryourtracks.eff.org.

Your roadmap

Full map: roadmap.sh/cyber-security.

Fundamental IT skills

  1. Hardware and connections: Wi-Fi, Bluetooth, NFC
  2. Operating systems: the GUI and the command line
  3. Networking: ping, traceroute, dig, arp, nmap, tcpdump
  4. Virtualization: VirtualBox or Multipass
  5. Everyday software, and its sharing settings

Then add Python, SQL, cloud basics and reading logs. You only need networking and operating systems to start.

Where people start

Entry roles

SOC Analyst (Tier 1), IT Support moving into security, governance and compliance (GRC), junior penetration tester, application security.

Where data meets security

Data analysts, engineers and scientists, ML engineers, security analysts and detection engineers all work with the same logs and pipelines.

Certifications, honestly

Start here

CompTIA A+, Linux+, Network+, CCNA, and Security+ (the one HR filters often look for).

Later, often employer-funded

CEH, OSCP, CREST, GIAC, CISA, CISM, and CISSP (which needs five years of experience).

Certifications open the door. Public writeups and real skill get you through it.
