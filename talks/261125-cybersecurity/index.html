Verify through a second channel

What "a second channel" means: when a message asks for money, a password or a click, confirm it a different way before you act. A friend asks for money in chat: call them on a number you already have. The bank emails a link: open the bank app yourself. Never check by replying to the same message, because the scammer controls it.

Commands from the session

These run in the Terminal app on macOS. Most also work on Linux; where they differ, the Linux version is in the comment.

The rule. Only scan, probe or test machines you own or have written permission to test. Doing it to anyone else's system is a crime under the Cybercrime Prevention Act (RA 10175) and carries a prison sentence. Everything below runs on your own computer.

The machine alone: accounts and permissions

$ whoami                                  # the account, not the person
$ mkdir -p ~/demo && echo "my secret plans" > ~/demo/secret.txt
$ ls -l ~/demo/secret.txt                 # -rw-r--r--  owner can write, everyone can read
$ ps -eo pid,user,comm | head -15         # programs running right now
$ chmod 000 ~/demo/secret.txt             # nobody may read it
$ cat ~/demo/secret.txt                   # Permission denied
$ sudo cat ~/demo/secret.txt              # privilege escalation: the admin reads it anyway
$ chmod 644 ~/demo/secret.txt             # reset

Reading -rw-r--r--: the first character is the type, then three letters each for the owner, the group and everyone. r read, w write, x execute, - no.

Your machine on the local network

$ ipconfig getifaddr en0                  # your private IP (try en1)   Linux: ip -4 addr
$ route -n get default | grep gateway     # your router                 Linux: ip route
$ ping -c 4 $(route -n get default | awk '/gateway/ {print $2}')
$ arp -a                                  # devices your machine has talked to

The journey out

$ traceroute -n -q 1 -w 1 example.com     # every line is a different machine on the route

Ports: close every door you are not using

A port is a numbered door on a computer. If no program is listening, there is no door. A firewall set to default deny keeps everything closed unless you allow it.

$ lsof -iTCP -sTCP:LISTEN -n -P           # programs listening on your own machine   Linux: ss -tlnp

Social engineering: spot the phish

Social engineering is tricking a person instead of breaking a machine. It works by pushing on feelings: urgency, authority, fear, trust, curiosity and scarcity. Every scam in the session had one tell. Learn the tells, not the messages.

SMS"Verify your e-wallet account" with a linkA lookalike link domain. Open the app yourself instead.

When it is aimed at you (spear phishing)

  • The best friend who needs money. The account, the nickname and the writing style all look right, because the account was taken over. Call them on a number you already have.
  • "Guys, favor, please like this" in the group chat. The link opens a fake login page. Check the address bar before you type a password, and open the app yourself instead.
  • "Post your mother's maiden name if you are proud of her." Fun posts like this collect the answers to your security questions. Do not answer them.

Bad grammar used to be the tell. AI removed it. The rule that still works: verify through a second channel you already trust. If you already clicked or paid, tell someone and report it quickly. Speed matters more than embarrassment.

How passwords should be stored

The eight steps of the password ladder, from worst to best. If you build a login, aim for the bottom of the list.

  1. Plaintext. One leak and every account is gone.
  2. Hashed. Unreadable, but not safe yet.
  3. Rainbow tables. Attackers do not crack common passwords, they look them up.
  4. The second leak. The same stored value means the same password.
  5. Salt. A random value per user, so the same password stores differently and lookups fail.
  6. Still guessable. Fast hashes allow billions of guesses a second. Salt made them work, not slow.
  7. Slow hashing. Use bcrypt, scrypt or Argon2, which are designed to be slow.
  8. Pepper, and after a leak. Keep a secret outside the database. After a leak: reset passwords, end every session, re-hash, notify within 72 hours, and check for reused passwords.

Check your own email at haveibeenpwned.com, and see what your browser gives away at coveryourtracks.eff.org.

Protecting other people's data

At home you protect your own data. In a company you protect data that belongs to customers, so the Data Privacy Act (RA 10173) applies: the company must name a Data Protection Officer and report a breach within 72 hours.

Personal information (PII) is anything that points to one person, alone or combined: a name, an email, a phone number, a government ID, or a birth date plus a city.

Your roadmap

Full map: roadmap.sh/cyber-security.

Fundamental IT skills

  1. Hardware and connections: Wi-Fi, Bluetooth, NFC
  2. Operating systems: the GUI and the command line
  3. Networking: ping, traceroute, dig, arp, nmap, tcpdump
  4. Virtualization: VirtualBox
  5. Everyday software, and its sharing settings

Then add Python, SQL, cloud basics and reading logs. Learn as much of this as you can. AI now handles the easy tasks, so the people who get hired are the ones who understand how it all works.

What the roadmap covers

Common ground, the same for everyone: IT basics, operating systems, networking, security concepts and one scripting language. After that, every career mixes three areas differently:

Attack skills

Find the holes before a criminal does: penetration testing and web app testing. Always with permission.

Defense skills

Watch, detect, respond: reading logs, handling alerts, incident response, hardening systems.

Governance

Set the rules and prove they are followed: risk, policy, audits, and laws such as the Data Privacy Act.

Where people start

A typical order, not a required one.

  1. IT help desk / support technician. Solves users' problems, manages accounts and access, and spots everyday security problems like phishing or malware.
  2. Junior system administrator. Keeps operating systems running, applies patches, and manages user permissions.
  3. Network support / junior network administrator. Monitors network traffic, supports routers and switches, and helps enforce network security.
  4. SOC analyst. Watches security alerts around the clock and investigates anything odd.
  5. Compliance (GRC). Checks that the company follows its own rules and the law.
  6. Application security. Reviews software for vulnerabilities and helps developers fix them.
  7. Junior penetration tester. Attacks the company's own systems, with written permission, to find holes first.

Or bring security into another job. Software developers check every input and protect logins. Data engineers and analysts decide who can see the data and mask personal data. Cloud and DevOps engineers close open settings and manage keys and access. Nobody gets hired to hack. They get hired because they understand how systems work.

Certifications, honestly

Start here

CompTIA A+, Linux+, Network+, CCNA, and Security+ (the one HR filters often look for).

Later, often employer-funded

CEH, OSCP, CREST, GIAC, CISA, CISM, and CISSP (which needs five years of experience).

Certifications open the door. Public writeups and real skill get you through it.
